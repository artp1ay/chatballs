## 1. Введение и цели проектирования

Настоящая спецификация описывает пользовательский опыт (UX), структуру экранов (UI), интерактивные состояния компонентов, сценарии взаимодействия и текстовые формулировки (UX Writing) для функционала **гибкой маршрутизации диалогов и правил подключения AI-агентов** платформы Chatballs.

### Ключевые цели интерфейса:
1. **Бизнес-гибкость:** Предоставить руководителям поддержки и администраторам возможность гибко выбирать, кто и когда отвечает клиентам (только люди, ИИ-ассистент или гибридная схема по правилам).
2. **Нулевой порог входа (Zero-Code Rules):** Конструктор правил должен быть понятен старшему оператору или супервайзеру без навыков программирования и знания регулярных выражений.
3. **Чистота языка (No Dev Jargon):** Полный запрет на отображение технических терминов, кодов енумов и внутренних идентификаторов. Интерфейс говорит на языке заботы о клиенте.
4. **Прозрачность статуса диалога для оператора:** Оператор в любой момент времени однозначно видит, кто ведет переписку (ИИ, коллега или обращение ждет в очереди), и может перехватить диалог в один клик или отправкой первого сообщения.
5. **Соответствие дизайн-системе Consta UI:** Использование проверенных компонентов `@consta/uikit`, семантических токенов и полноценная поддержка темной и светлой тем.

### 2.3. Спецификация режимов и UX Writing

| Режим в UI | Иконка Consta | Заголовок карточки | Описание под заголовком | Информационный баннер (`Informer`) при выборе |
|---|---|---|---|---|
| **Только сотрудники** | `IconUser` / `IconTeam` | **Только сотрудники** | Диалоги сразу поступают в очередь операторам. ИИ-агент отключен от публичных ответов в чат. | `status="system"`: *«В этом режиме виртуальный ассистент не отвечает клиентам. Все новые сообщения мгновенно распределяются между свободными сотрудниками согласно настройкам очередей.»* |
| **По правилам** | `IconLayers` / `IconShuffle` | **По правилам** | Обращения распределяются гибко: по графику работы (день/ночь), VIP-статусу клиентов или темам сообщений. | `status="system"`: *«Включена гибкая маршрутизация. Платформа проверяет правила по очереди сверху вниз. Настройте рабочие часы и правила распределения ниже.»* |
| **ИИ-агент по умолчанию** | `IconSun` / `IconLightning` | **ИИ-агент по умолчанию** | Виртуальный ассистент встречает всех клиентов, отвечает на типовые вопросы и зовет человека при необходимости. | `status="system"`: *«Классический режим быстрого ответа. ИИ берет на себя первичную обработку диалогов. Если клиент просит человека или вопрос сложный, диалог передается в очередь.»* |

### 2.4. Компонентный состав и интерактивные состояния
- **Карточки выбора режима:**
  - Реализуются через кастомный селектор на базе `Card` с `Radio` внутри либо `ChoiceGroup`.
  - **Default:** Фон `var(--color-bg-default)`, граница `1px solid var(--color-bg-border)`, радиус `var(--radius-m)` (8px), отступы `space-m` (16px).
  - **Hover:** Граница `1px solid var(--color-typo-brand)`, курсор `pointer`, плавный переход `transition: border-color 0.15s ease`.
  - **Selected (Активен):** Граница `2px solid var(--color-control-bg-primary)`, фон с легким брендовым оттенком `var(--color-bg-stripe)`, радиокнопка отмечена `checked`.
  - **Disabled:** Прозрачность `0.5`, курсор `not-allowed`, текст `var(--color-typo-ghost)`.
- **Информационный баннер:** Компонент `<Informer view="bordered" status="system">`, отступ сверху `space-m`.
- **Кнопки управления:**
  - `<Button view="primary" label="Сохранить изменения" size="m">`
  - `<Button view="ghost" label="Отменить" size="m">`
- **Обратная связь:** При нажатии «Сохранить изменения» отображается уведомление `<SnackBar items={[{ message: "Режим обработки обращений успешно обновлен", status: "success" }]}>`.

### 3.3. Детальная спецификация элементов и валидации

1. **Выбор часового пояса (`Combobox` / `Select`):**
   - Компонент `<Select placeholder="Выберите часовой пояс" items={timezonesList} search />`.
   - Поддерживает поиск по городам (Москва, Екатеринбург, Владивосток, Лондон, Алматы, Минск) и смещению UTC.
   - Под полем выводится живой индикатор текущего времени: *«Текущее локальное время канала: 15:42»*.

2. **Быстрые пресеты расписания:**
   - Кнопка `<Button view="secondary" size="s" label="Стандартный 5/2 (09:00 - 18:00)">`: мгновенно заполняет Пн–Пт интервалом 09:00–18:00, Сб и Вс переводит в статус «Выходной».
   - Кнопка `<Button view="secondary" size="s" label="Круглосуточно (24/7)">`: выставляет все 7 дней активными с 00:00 до 23:59 без перерывов.

3. **Сетка дней недели:**
   - Чекбокс активности дня `<Checkbox checked={day.isActive} label={day.name} />`.
   - При выключенном чекбоксе: поля времени скрываются или блокируются, отображается статус-текст *«Выходной день»* цветом `var(--color-typo-ghost)`.
   - Поля ввода времени: `<TextField type="time" value={day.start} size="s" />` — `<TextField type="time" value={day.end} size="s" />`.
   - Блок перерыва: по клику на «+ Добавить перерыв» появляется строка интервала с кнопкой удаления `IconTrash`.
   - **Валидация:**
     - Время окончания смены не может быть раньше времени начала.
     - Время начала перерыва должно быть строго позже начала смены, а окончание перерыва — раньше окончания смены.
     - При ошибке валидации поле подсвечивается `status="alert"`, под полем выводится поясняющий текст: *«Время окончания должно быть позже времени начала»*.

4. **Праздничные и нерабочие дни:**
   - Список уже добавленных дат отображается в виде бейджей-тегов `<Tag label="01.01.2026" onCancel={handleRemove} size="m" />`.
   - Кнопка «+ Добавить праздничную дату» открывает компактный всплывающий календарь `<DatePicker />`.
   - Кнопка «Загрузить праздники РФ на 2026 год» автоматически импортирует официальный нерабочий календарь без ручного ввода.

| **Метки клиента** | Теги в карточке CRM / контакта | «Содержит метку», «Не содержит метку» | Мультивыбор тегов `<Select multiple items={tags} />` |
| **Ключевые слова в сообщении** | Поиск стоп-слов или тем обращения | «Содержит любое из слов», «Содержит точную фразу», «Не содержит слов» | Текстовые чипсы `<TextField placeholder="Введите слова через Enter" />` |
| **Телефон клиента** | Наличие контакта в профиле | «Указан и подтвержден», «Не указан» | Не требуется |
| **Первое обращение** | Новый клиент или повторный | «Да (первое обращение)», «Нет (повторный диалог)» | Не требуется |

### 4.4. Доступные действия и группы назначения
1. **Направить ИИ-агенту:**
   - Если у канала несколько агентов: выбор целевого виртуального ассистента.
   - Пояснение: *«Диалог моментально получит ответ от ИИ. Оператор сможет перехватить диалог при необходимости.»*
2. **Направить сотрудникам поддержки:**
   - Выбор группы назначения:
     * «Общая очередь (любой свободный оператор)»
     * «Первая линия поддержки»
     * «Технические специалисты»
     * «Финансовый отдел и биллинг»
     * «Отдел по работе с VIP-клиентами»
   - Пояснение: *«Диалог будет поставлен в очередь выбранной группы. ИИ не будет отвечать клиенту.»*

### 5.2. Спецификация бейджей статуса контроллера диалога

В шапку диалога помещается компонент `<Badge>` с фиксированными стилями и семантическими статусами Consta:

| Статус диалога | Компонент Consta | Иконка | Текст бейджа | Всплывающая подсказка (`Tooltip`) |

### 5.3. Механика действия «Взять диалог на себя»
- **Кнопка:** `<Button view="primary" iconLeft={IconHand} label="Взять диалог" size="s">`.
- **Доступность:** Отображается и активна, если диалог находится в статусе `ИИ-агент` или `В очереди`.
- **Поведение по клику:**
  1. Кнопка переходит в состояние загрузки `<Button loading />`.
  2. Диалог мгновенно закрепляется за текущим оператором.
  3. Бейдж в шапке меняется на зеленый `Назначен вам`.
  4. В ленте сообщений выводится разделитель системного события: *«Вы подключились к диалогу. ИИ-ассистент переведен в режим наблюдения»*.
  5. Фокус клавиатуры автоматически перемещается в поле ввода текста.

### 5.4. Механика действия «Передать ИИ-агенту» с диалогом подтверждения
- **Расположение:** В выпадающем меню кнопки `<ActionMenu items={[{ label: "Передать ИИ-агенту", icon: IconRobot }]}>` в шапке чата.
- **Модальное окно подтверждения (`Modal`):**

```
┌──────────────────────────────────────────────────────────────────┐
│  Передать диалог ИИ-агенту?                                  [✕] │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Клиент продолжит общение с виртуальным ассистентом.             │
│  ИИ получит всю историю переписки и ответит на следующее         │
│  входящее сообщение клиента.                                     │
│                                                                  │
│  [✓] Добавить краткую заметку для ИИ-агента                      │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │ Клиент запросил акт сверки за 2 квартал, номер договора... │  │
│  └────────────────────────────────────────────────────────────┘  │
│                                                                  │
│  Вы в любой момент сможете снова перехватить переписку.          │
│                                                                  │

│  [ Передать ИИ-агенту ]                             [ Отмена ]   │
└──────────────────────────────────────────────────────────────────┘
```

- **Спецификация кнопок модального окна:**
  - `<Button view="primary" label="Передать ИИ-агенту">`
  - `<Button view="ghost" label="Отмена">`
- **Результат подтверждения:** Статус диалога меняется на `ИИ-агент`, в ленте отображается системная плашка: *«Диалог передан виртуальному ассистенту»*.

### 5.5. Предупреждающий баннер о перехвате диалога отправкой сообщения
- **Компонент:** `<Informer view="filled" status="warning" icon={IconAlert} size="s">`.
- **Расположение:** Прямо над областью ввода текста (прикреплен к верхней границе редактора).
- **Логика показа:** Появляется **только тогда**, когда оператор открыл чат, в котором текущий контроллер — `ИИ-агент`.
- **Текст:** *«Сейчас на сообщения отвечает ИИ-агент. Отправка вашего ответа автоматически переведет диалог на вас, и бот перестанет отвечать.»*
- **Бесшовный UX (Seamless Handover):**
  - Оператору не требуется делать лишний клик по кнопке «Взять диалог».
  - Как только оператор нажимает Enter или кнопку «Отправить», бэкенд переводит управление диалогом на оператора, отправляет сообщение клиенту, а баннер мгновенно скрывается с плавной анимацией исчезновения (`fade-out 0.2s`).

### 7.2. Токены Consta UI для темной темы (`presetChatballsDark`)

- Второстепенный текст: `var(--color-typo-secondary)` (#94A3B8 в темной теме, #475569 в светлой).
- Акцентный брендовый цвет: `var(--color-control-bg-primary)` (#6366F1 / Indigo).
- Предупреждающий цвет (баннер перехвата, очередь): `var(--color-bg-warning)` (#FEF3C7 в светлой теме, #3B2D05 в темной).

## 8. Критерии готовности (Definition of Done) для Frontend-разработчика

1. **Режим обработки обращений:**
   - [ ] В карточке настроек канала реализован блок выбора из 3 карточек-режимов.
   - [ ] Выбор карточки сопровождается сменой поясняющего информационного баннера `Informer`.
   - [ ] При сохранении отправляется `PATCH /api/channels/{id}/` с полем `routing_mode`.
2. **График работы:**
   - [ ] Выпадающий список часовых поясов с поиском и отображением локального времени.
   - [ ] Сетка 7 дней недели с чекбоксами активности, валидацией временных интервалов и кнопками перерывов.
   - [ ] Календарный выбор праздничных дат и отображение тегами.
   - [ ] Сохранение через `PUT /api/channels/{id}/business-hours/`.
3. **Конструктор правил:**
   - [ ] Список правил с Drag-and-Drop или кнопками изменения приоритета.
   - [ ] Переключатель активности правила без перезагрузки страницы.
   - [ ] Выдвижная боковая панель (Sidebar) добавления/редактирования правила.
   - [ ] Конструктор условий (И / ИЛИ, параметры: график, метки, ключевые слова).
   - [ ] Карточка действия по умолчанию внизу списка.
4. **Рабочее место оператора:**
   - [ ] Отображение бейджей контроллера диалога в шапке чата (`ИИ-агент`, `В очереди`, `Назначен вам`).
   - [ ] Кнопка «Взять диалог на себя» с мгновенным обновлением состояния.
   - [ ] Меню действия «Передать ИИ-агенту» с модальным окном подтверждения.
   - [ ] Предупреждающий баннер над полем ввода при открытом чате с ИИ-контроллером.
   - [ ] Автоматический бесшовный перехват диалога при отправке сообщения оператором.
5. **Дизайн-система и доступность:**
   - [ ] 100% компонентов импортируются из `@consta/uikit` и `@consta/icons`.
   - [ ] Корректное отображение в светлой (`presetDefault`) и тёмной (`presetDark`) темах.
   - [ ] Полное отсутствие служебной лексики и кодов enum в текстах интерфейса.
