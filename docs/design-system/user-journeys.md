# Пользовательские сценарии (User Journeys) и передача в разработку

## 1. Пользовательские сценарии взаимодействия (UX Scenarios)

### Сценарий UX-1: Обработка обращения оператором поддержки (Internal UI)

```
[Поступление тикета] ──> [Уведомление / Снекбар] ──> [Выбор диалога в списке]
         │
         ▼
[Изучение контекста клиента в правой панели] ──> [Просмотр истории и CRM-тегов]
         │
         ▼
[Ввод ответа (шаблон '/' или AI-черновик)] ──> [Редактирование и отправка]
         │
         ▼
[Завершение диалога / Выставление категории обращения]
```

1. **Поступление нового обращения:**
   - Воспроизводится звуковой сигнал (`resources/notification.mp3`).
   - У пункта «Диалоги» в `Sidebar` обновляется счётчик `Badge status="error"`.
   - В правом верхнем углу появляется системный тост `SnackBar` с именем клиента и превью сообщения.
2. **Переход в диалог:**
   - Оператор выбирает строку диалога в левом списке.
   - Список подсвечивает активный чат стилем `Row Selected`, счётчик непрочитанных сообщений сбрасывается.
   - Центральная колонка загружает историю переписки.
3. **Изучение контекста:**
   - В правой панели отображается карточка клиента `Card`: имя, компания, часовой пояс, контакты, теги `Tag`.
   - Если клиент новый — отображается плашка с предложением привязать контакт.
4. **Формирование ответа:**
   - Оператор вводит символ `/` в поле `TextField` — появляется всплывающее меню `ContextMenu` со сниппетами быстрых ответов.
   - Либо оператор нажимает кнопку «Сгенерировать ответ AI» — появляется блок с черновиком ответа нейросети с кнопками «Принять», «Править» и «Отклонить».
   - Оператор отправляет сообщение клавишами `Ctrl + Enter` или кликом на `Button view="primary" iconRight={IconSend}`.
5. **Завершение обработки:**
   - Оператор кликает «Завершить диалог», в открывшемся `Modal` выбирает категорию обращения и подтверждает архивацию.

### Сценарий UX-2: Взаимодействие клиента с виджетом Web Chat

```
[FAB кнопка на сайте] ──> [Клик / Раскрытие окна] ──> [Приветствие / Consent]
         │
         ▼
[Отправка вопроса / Вложение файла / Голосовое сообщение]
         │
         ▼
[Индикатор "Печатает..." ──> Получение ответа оператора или AI]
         │
         ▼
[Входящий звонок / Переход в Call Stage ──> Успешное решение проблемы]
```

1. **Вход в диалог:**
   - Клиент замечает плавающую кнопку (FAB) `56x56px` в правом нижнем углу сайта.
   - Клик по кнопке плавно раскрывает окно виджета (`380x620px`).
   - Показывается карточка согласия с политикой конфиденциальности и кнопкой «Начать чат» (`Button view="primary" size="l"`).
2. **Отправка сообщения и медиа:**
   - Клиент вводит вопрос в текстовое поле `TextField`.
   - Нажимает на кнопку со скрепкой (`IconAttach`) для прикрепления файла или скриншота.
   - Удерживает кнопку микрофона (`IconMicrophone`) для записи голосового сообщения. При записи появляется таймер и пульсирующая волна.
3. **Получение ответа:**
   - В ленте появляется анимированный индикатор набора текста («Оператор печатает...»).
   - Приходит ответ с аватаром оператора, разметкой Markdown и ссылками.
4. **Голосовой / видеозвонок:**
   - Оператор отправляет приглашение к аудио/видеовызову.
   - В виджете чата появляется баннер звонка с кнопками «Принять» (зеленая) и «Отклонить» (серая).
   - При принятии клиент переходит в полноэкранный интерфейс звонка `CallStage` с нативными кнопками управления микрофоном и камерой Consta.

## 2. Поэтапный план реализации (Handoff to Frontend)

Миграция на Consta UI декомпозируется на 5 последовательных этапов:

### Этап 1: Инфраструктура дизайн-системы (`@chatballs/ui`)
- Установка зависимостей `@consta/uikit`, `@consta/icons`, `@consta/header`.
- Создание файлов темы: `presetChatballsDefault`, `presetChatballsDark` в `packages/ui/src/theme.ts`.
- Экспорт провайдера `<Theme preset={...} />`.

### Этап 2: Базовые переиспользуемые компоненты (`@chatballs/ui`)
- Миграция индикатора загрузки `Loader`.
- Миграция интерфейсов аудиовызовов `AudioCallView`, `AudioCallWaveform` на компоненты Consta (`Button`, `Text`).

### Этап 3: Клиентский веб-чат (`@chatballs/web-chat`)
- Перевод шапки `ChatHeader`, поля ввода `ChatComposer`, ленты сообщений `ChatBody` на Consta UI.
- Полное удаление `antd` из `apps/web-chat/package.json`.

### Этап 4: Внутренний интерфейс оператора (`@chatballs/internal-ui`)
- Перевод общего каркаса `Shell`, навигации `Sidebar`, шапки на `Layout` и `Sidebar` Consta.
- Замена списков и таблиц диалогов и клиентов на Consta `Table` и `Pagination`.
- Перевод форм настроек, профиля и сотрудников на `TextField`, `Select`, `Switch`.
- Полное удаление `antd` и `@ant-design/icons` из `apps/internal-ui/package.json`.

### Этап 5: Верификация и критерии готовности (Definition of Done)
- [ ] Во всех пакетах отсутствуют зависимости `antd` и `@ant-design/icons`.
- [ ] Светлая и тёмная темы работают корректно без искажений контраста и сброса стилей.
- [ ] Все интерактивные состояния кнопок, полей ввода и таблиц соответствуют спецификации.
- [ ] Код проходит проверку типов `pnpm typecheck` и тесты `pnpm test`.
