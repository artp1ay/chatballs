# ADR: Frontend-архитектура и дизайн-бейзлайн раздела Heldesk

- **Статус:** Принято к реализации
- **Ответственный архитектор:** CTO
- **Исполнитель реализации:** Frontend Dev
- **Связанные задачи:** [HOM-30](/HOM/issues/HOM-30), [HOM-47](/HOM/issues/HOM-47), [HOM-49](/HOM/issues/HOM-49)

---

## 1. Контекст и цели

После реализации серверного ядра модуля заявок (`chatballs.tickets`, [HOM-47](/HOM/issues/HOM-47)) необходимо разработать полнофункциональный пользовательский интерфейс Heldesk во внутреннем веб-приложении операторов и руководителей (`apps/internal-ui`).

Интерфейс должен быть глубоко интегрирован в экосистему Chatballs, гармонично соответствовать дизайн-системе Consta UI (`@consta/uikit`), поддерживать оперативное создание заявок прямо из активного чата, разграничивать внутренние заметки и публичные комментарии, а также строго соблюдать правила доступности WCAG 2.2 AA и лимит размера файлов (NO GOD FILES: < 300 строк на файл).

---

## 2. Структура директории `apps/internal-ui/src/features/tickets/`

В соответствии с правилом модульности и ограничением размера файлов, функционал выносится в отдельную feature-директорию:

```text
apps/internal-ui/src/features/tickets/
├── types.ts                   # Интерфейсы тикетов, событий, заметок, фильтров и пагинации
├── api.ts                     # Клиентские методы работы с backend REST API тикетов
├── model.ts                   # Доменные хелперы, маппинг статусов/приоритетов на цвета Consta
├── TicketsPage.tsx            # Реестр заявок: тулбар фильтров, поиск, таблица, keyset-пагинация
├── TicketsTable.tsx           # Табличное представление списка тикетов с бейджами статусов/приоритетов
├── TicketFiltersBar.tsx       # Панель фильтрации (статус, приоритет, группа, ответственный, поиск)
├── TicketDetailPage.tsx       # Детальная карточка заявки: шапка, смена статусов, вкладки
├── TicketStatusActions.tsx    # Кнопки переходов состояний и модальные окна подтверждения с причиной
├── TicketCommentsTab.tsx      # Публичные комментарии с чекбоксом «Не уведомлять клиента»
├── TicketNotesTab.tsx         # Внутренние заметки команды с защитным визуальным акцентом
├── TicketTimelineTab.tsx      # Хроника событий аудита (TicketEvent)
├── CreateTicketModal.tsx      # Модальное окно создания заявки (standalone и из чата)
├── RelatedTicketsSection.tsx  # Виджет связанных заявок для карточки клиента/диалога в чате
├── tickets.css                # Стили раздела (согласованные с токенами Consta и темой Chatballs)
└── __tests__/
    ├── ticketsModel.test.ts   # Тестирование доменной логики, фильтров и маппинга статусов
    └── ticketsApi.test.ts     # Тестирование обработки 409 Conflict и API вызовов
```

## 3. Дизайн-бейзлайн и маппинг компонентов Consta UI

Все элементы интерфейса строятся на базе компонентов `@consta/uikit` и единой дизайн-системы Chatballs:

### 3.1 Статусы и приоритеты заявок
- **Статусы (`TicketStatus`):**
  - `NEW` (Новая): бейдж `status="system"`, нейтральный синий/серый тон.
  - `IN_PROGRESS` (В работе): бейдж `status="normal"`, акцентный синий/фиолетовый.
  - `WAITING_CUSTOMER` (Ожидание клиента): бейдж `status="warning"`, янтарно-оранжевый.
  - `RESOLVED` (Решена): бейдж `status="success"`, зеленый.
  - `CLOSED` (Закрыта): бейдж `status="normal"`, серый приглушенный.
  - `CANCELLED` (Отменена): бейдж `status="alert"`, красный.
  - `DUPLICATE` (Дубликат): бейдж `status="system"`, приглушенный.
- **Приоритеты (`TicketPriority`):**
  - `LOW` (Низкий): `Tag` / `Badge` нейтрального спокойного тона.
  - `NORMAL` (Обычный): стандартный тон.
  - `HIGH` (Высокий): оранжевый янтарный акцент.
  - `URGENT` (Срочный): ярко-красный акцент со значком пламени/восклицания.

### 3.2 Реестр заявок (`TicketsPage`)
- **Заголовок страницы:** `PageHeader` с заголовком «Heldesk», счетчиком общего числа заявок и основной кнопкой «Создать заявку» (`Button` с иконкой `plus`).
- **Фильтрация и поиск (`TicketFiltersBar`):**
  - Поле текстового поиска с debounce (`TextField` со значком лупы) по номеру и теме.
  - Селекты фильтрации (`SelectMenu` или `Select` из Consta):
    - Статус (множественный выбор или «Все статусы»);
    - Приоритет;
    - Ответственный сотрудник;
    - Группа сотрудников.
  - Кнопка «Сбросить фильтры».
- **Таблица реестра (`TicketsTable`):**
  - Колонки: Номер заявки (ссылка на детальную карточку), Тема, Клиент (`requester_contact`), Статус (`Badge`), Приоритет, Группа/Ответственный, Дата обновления.
  - Состояние загрузки: скелетоны `Loader` / `Skeleton`.
  - Пустое состояние: `ContentState` («Заявки не найдены» с предложением сбросить фильтры или создать заявку).
- **Пагинация:** компонент `Pagination` с выбором размера страницы (`window_size`: 20, 50, 100) и ключами курсоров.

### 3.3 Детальный вид заявки (`TicketDetailPage`)
- **Шапка карточки:**
  - Номер заявки (крупный шрифт, тег для быстрого копирования), тема заявки с возможностью редактирования.
  - Метаданные: дата создания, последнее обновление, инициатор (ссылка на контакт в CRM/Чате), ответственный, рабочая группа.
  - Панель переходов статуса (`TicketStatusActions`):
    - Отображаются только допустимые целевые статусы в соответствии со State Machine (`NEW` -> `IN_PROGRESS` -> `RESOLVED` / `CLOSED` и т.д.).
    - Для переходов в `RESOLVED`, `CLOSED`, `CANCELLED` открывается модальное окно (`ConstaModal`) с обязательным полем ввода причины (`reason`).
  - Оптимистическая блокировка (Optimistic Concurrency):
    - При отправке перехода передается текущий `expected_version: ticket.version`.
    - При получении `409 Conflict` пользователю выводится информирующее предупреждение с кнопкой «Обновить данные», не позволяя затереть чужие изменения.
- **Вкладки взаимодействия (`Tabs`):**
  1. **Публичные комментарии (`TicketCommentsTab`):**
     - Список комментариев (сообщения операторов и клиента).
     - Поле ввода нового комментария с формой отправки.
     - **Обязательный чекбокс:** «Не уведомлять клиента» (`Checkbox` из Consta) с поясняющей подсказкой.
  2. **Внутренние заметки команды (`TicketNotesTab`):**
     - Выделенный визуальный стиль карточек заметок (желтый фон / рамка `is-internal-note`, значок замка), наглядно сигнализирующий, что эти сообщения никогда не видны клиенту.
     - Форма быстрого добавления внутренней заметки.
  3. **Хроника заявки (`TicketTimelineTab`):**
     - Вертикальный таймлайн (`TicketEvent`) с отображением изменений статусов, переназначений, добавления заметок, автора действия и признака уведомления клиента.

## 4. Интеграция с чатом (`ConversationWorkspace`)

### 4.1 Кнопка создания заявки из диалога
В компоненте `ConversationThread.tsx` в шапку действий (`sales-conversation-actions`) добавляется кнопка:
```tsx
<button
  className="sales-secondary-action"
  type="button"
  onClick={() => setCreateTicketOpen(true)}
  title={t("tickets.create_ticket_from_chat")}
>
  <Icon name="ticket" size={15} />
  <span>{t("tickets.create_ticket")}</span>
</button>
```

### 4.2 Модальное окно быстрого создания (`CreateTicketModal`)
- При открытии из диалога чата:
  - Автоматически предзаполняются: контакт клиента (`conversation.contact`), канал обращения (`conversation.channel`), а также исходный диалог (`conversation.id`).
  - Тема по умолчанию: краткая выжимка или последнее сообщение диалога.
  - Выбор приоритета, категории и назначения сотрудника/группы.
- Запрос отправляется на эндпоинт `POST /api/v1/organizations/{org_id}/conversations/{conv_id}/ticket/`.
- После успешного создания: всплывающее уведомление (Toast/Alert) с кликабельным номером созданной заявки и автоматическое обновление блока «Связанные заявки».

### 4.3 Блок «Связанные заявки» в контекстной панели диалога (`ClientContext.tsx`)
В контекстную панель диалога (под блоком контакта) встраивается секция `RelatedTicketsSection`:
- Заголовок «Заявки клиента» с количеством активных заявок.
- Компактный список заявок: номер, тема, текущий статус (`Badge`), дата.
- Клик по заявке открывает детальную страницу тикета.
- Кнопка «+ Новая заявка».

## 5. Роутинг и навигация

В `apps/internal-ui/src/`:
1. `types.ts`:
   - Добавить роуты в `RouteKey`: `"tickets" | "ticketDetail"`.
   - В `RouteState`: добавить `ticketId: number | null`.
2. `router.ts`:
   - Маршрут `/tickets` -> `{ route: "tickets", ticketId: null }`.
   - Маршрут `/tickets/:id` -> `{ route: "ticketDetail", ticketId: Number(id) }`.
   - `pathFromRoute`: формирование `/organizations/{org_id}/tickets` и `/organizations/{org_id}/tickets/{ticketId}`.
3. `routes.ts`:
   - `tickets: t("common.tickets")`,
   - `ticketDetail: t("shared.ticket_detail")`.
4. `auth/access.ts`:
   - `canAccess`: роут `tickets` и `ticketDetail` доступен для `isManager(user)` и для сотрудников с capability `tickets.view`.
5. `layout/Sidebar.tsx`:
   - Добавить пункт меню «Заявки» (`tickets`) с иконкой `ticket` для менеджеров и операторов с доступом.
6. `layout/ShellRouteContent.tsx`:
   - Ленивая загрузка (`lazy`) страниц `TicketsPage` и `TicketDetailPage`.

## 7. Критерии приёмки для Frontend Dev (Definition of Done)

1. Раздел «Заявки» доступен в основном меню и корректно открывается по адресу `/tickets` и `/tickets/:id`.
2. Список заявок корректно фильтрует данные по статусам, приоритетам, группам, ответственным и строке поиска.
3. Карточка заявки позволяет просматривать детали, переводить статусы с вводом причины, добавлять внутренние заметки и публичные комментарии с чекбоксом «Не уведомлять клиента».
4. Внедрена обработка `409 Conflict` (Optimistic Concurrency) при одновременном редактировании.
5. В активном диалоге чата присутствует кнопка «Создать заявку», модальное окно предзаполняет данные клиента и диалога, а блок «Связанные заявки» отображает список тикетов контакта.
6. Интерфейс полностью построен на компонентах `@consta/uikit` и токенах дизайн-системы Chatballs.
7. Все тексты и сообщения локализованы на русском и английском языках (`ru.ts`, `en.ts`). Тест `catalog.test.ts` проходит без ошибок.
8. Все файлы строго удовлетворяют лимиту NO GOD FILES (< 300 строк на файл).
9. Проект успешно проходит проверку типов `npm run typecheck --workspace=@chatballs/internal-ui` и тесты `npm run test --workspace=@chatballs/internal-ui`.
